# セキュリティ上の注意

Lista を自分の組織で使ってよいかを判断するための材料です。配布元が受け入れたリスクと、その理由も書いています。同じ判断が自分の組織に当てはまるかを確かめてください。

## Lista が守っていること

- **ログインは IdP に任せ、パスワードを持ちません。** 「利用者」の画面に登録したメールアドレスの人だけがログインできます
- **Lista は 127.0.0.1 だけで待ち受けます。** 利用者の入口はリバースプロキシの https だけです（[リバースプロキシと https](reverse-proxy.md)）
- **画面にはコンテンツセキュリティポリシー（CSP）を付けています。** インラインのスクリプトを許さず、ほかのサイトへの埋め込みも許しません。Outlook のアドインのファイル（`/addin/` 以下）だけ、Outlook からの埋め込みを許しています
- ログインの Cookie には `Secure`・`HttpOnly`・`SameSite=Lax` を付けています
- ログインなしで開けるのは、ログインの画面・エラーの画面・`/actuator/health`（`{"status":"UP"}` だけを返す）・Outlook アドインのファイル・画面の部品（CSS・JavaScript・アイコン）だけです

## 利用者に役割の差がありません

登録した人は誰でも、すべての操作ができます。利用者の追加と無効化、テンプレートの変更、ほかの人への朝のまとめの送信も含みます。自分自身を無効にすることもできます。**使わせてよい人だけを登録してください。** 辞めた人や異動した人は、「利用者」の画面で無効にします（行は消せません）。

## 受け入れたリスク

### IP メッセンジャーの名乗りは確かめていません

朝のまとめと担当の知らせの宛先は、IP メッセンジャーの名乗り（ユーザー名・ニックネーム）で決めています。名乗りは自己申告です。LAN の誰かが他人の名前で IP メッセンジャーを起動すれば、その人宛ての通知が偽った側へ届き、本人は届かないことに気づけません。

配布元は、次の理由でこれを受け入れました。

- 漏れるのは、タスクの件名・期限・相手の名前です。金額や個人の機微な情報は通知に載せていません
- 偽れるのは、LAN（と VPN）の中にいる人に限られます
- IP メッセンジャーは暗号化しない UDP で、盗み聞きにも同じ程度に弱い。名乗りを確かめても、盗み聞きは防げません

LAN の中にいる人を信頼できない環境では、IP メッセンジャーの経路を使わないでください。同梱の compose の既定では使いません。

### ntfy のトピック名を合言葉にしています

同梱の ntfy は、`lista-*` のトピックを誰でも読めるように設定します（書けるのは Lista だけです）。購読する URL を知った人は、ntfy に届く場所から、その人の通知を読めます。

配布元は、上の 3 つに加えて、次の理由でこれを受け入れました。

- トピック名は、Lista が 130 ビットの乱数で作ります。利用者には選ばせません。漏れたら、本人が「自分の設定」で作り直せます
- 人ごとに購読のトークンを配る手間に比べ、防げるのは LAN の中の盗み読みだけで、暗号化しない IP メッセンジャーと変わりません

ntfy を LAN の外（インターネット）から届く場所に置くときは、この判断を見直してください。

## 運用でしてほしいこと

- `.env` には秘密の値が入ります。ほかの人が読めない権限（例: `600`）にしてください
- IdP のクライアントシークレット・Claude API の鍵・ntfy のトークンは、漏れたら作り直してください。クライアントシークレットは期限を控えてください
- バックアップのファイルには、業務のデータがすべて入っています。置き場所を限ってください
- 新しい版には、依存するライブラリの更新も入ります。Releases を見て、版上げを続けてください（[版上げ](upgrade.md)）
