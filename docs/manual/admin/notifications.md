# 通知の設定

Lista は、朝のまとめと担当になったときの知らせを、2 つの経路で送ります。どちらも任意で、使わなければ設定は要りません。

| 経路 | 届く先 | 要るもの |
|---|---|---|
| IP メッセンジャー | 各 PC の IP メッセンジャー | Lista をホストのネットワークで動かす（下の「IP メッセンジャー」） |
| ntfy | スマートフォンや PC の ntfy アプリ | ntfy のサーバー（同梱の compose で立てられる） |

利用者が「自分の設定」で ntfy を有効にすると、IP メッセンジャーに加えて ntfy にも送ります。受け取る側の操作は [利用者ガイドの通知の受け取り方](../user/notifications.md) にあります。

## 何をいつ送るか

| 種類 | いつ | 中身 |
|---|---|---|
| 朝のまとめ（IP メッセンジャー） | 月〜金の 6:00 以降に、その日初めてその人の IP メッセンジャーを見つけたとき | その人が担当の、済んでいないタスクのうち、期限切れ・今日・3 日以内のもの。担当未定のものは全員に載せる |
| 朝のまとめ（ntfy） | 月〜金の 8:30。送れなかった人などへは 18:30 まで毎時 30 分に | 上と同じ |
| 担当の知らせ | 突発タスクを作ったときと、担当を変えたとき | 担当になったタスクとサブタスク |
| 手動のまとめ・テスト送信 | 画面のボタンを押したとき | 朝のまとめと同じ・確認用の短い文 |

- 自動の朝のまとめは、経路ごとに 1 人 1 日 1 通です。載せるものが無ければ送りません
- 「見つけたとき」は 2 通りです。IP メッセンジャーを起動したとき（起動の知らせを受けたとき）と、8〜18 時の毎時 0 分に Lista が送る在席の確認に応答があったときです。在席の確認は土日も送ります
- 祝日は区別しません
- 通知に失敗しても、画面の操作は失敗にしません

## IP メッセンジャー

Lista は IP メッセンジャーのプロトコル（UDP 2425）で LAN に参加し、各 PC へ直接送ります。メンバーの一覧には「Lista」と出ます。

### ホストのネットワークで動かす

在席の知らせはブロードキャストで届くので、Docker の bridge ネットワークには届きません。同梱の [compose.ipmsg.yaml](../files/compose.ipmsg.yaml) を重ねて、Lista をホストのネットワークで動かします。

```bash
docker compose -f compose.yaml -f compose.ipmsg.yaml up -d
```

- ホストの UDP 2425 を Lista が使います。同じホストで IP メッセンジャーを動かさないでください。ポートを開けないときは、起動のログに出ます（その場合も、固定の通知先へは送れます）
- Lista はホストの `127.0.0.1:8080` で待ち受けます。DB はホストの `127.0.0.1:15432` に出します（変えるときは `.env` の `LISTA_DB_PORT`）
- ホストのファイアウォールで、LAN からの UDP 2425 を許可してください
- 在席の確認は `255.255.255.255` へ送ります。ルーターの都合で届かなければ、`.env` の `LISTA_IPMSG_BROADCAST` にセグメントのブロードキャストアドレス（例: `192.0.2.255`）を入れます。カンマで区切って複数を書けます
- ntfy も使うなら、`LISTA_NTFY_BASE_URL` は `http://127.0.0.1:2586` にします（ホストのネットワークからはサービス名を引けないため）

起動のログに `IPメッセンジャーの待ち受けを始めました. (port = 2425)` が出れば、待ち受けています。「利用者」の画面で、登録した人が「在席」になることを確かめてください。

### 宛先の決め方

各利用者が「自分の設定」で、自分の IP メッセンジャーのユーザー名かニックネームを登録します。Lista は、その名前で名乗った PC を探して送ります。IP アドレスが変わっても届きます。

- VPN など、ブロードキャストが届かない場所の人は、「固定の通知先」に PC の IP アドレスかホスト名を入れます。在席が見つからないときに、そこへ送ります
- 各 PC で、IP メッセンジャーの UDP 2425 の受信を許可しておきます（多くはインストールのときに聞かれます）
- Lista への返信は読みません

### 知っておくこと

- **IP メッセンジャーの通信は暗号化されません。** 通知の本文（タスク名・相手・期限など）は LAN を平文で流れます
- **名乗りは自己申告です。** LAN の中の誰かが他人の名前で名乗ると、その人宛ての通知を受け取れます（[セキュリティ上の注意](security.md)）
- IP メッセンジャー v5 で在席を見つけられることは、配布元で確かめました。v5 が、暗号化していないメッセージを表示するかは確かめていません。テスト送信が表示されないときは、受け取る側の設定を確かめてください

## ntfy

同梱の compose に ntfy のサーバーを入れてあります。`.env` で有効にするまでは起動しません（アクセスの制御をする前の ntfy を立てないためです）。

### 立て方

1. ntfy を開く URL（例: `https://ntfy.example.com`）を決め、`.env` に入れて ntfy だけを起動します

   ```bash
   COMPOSE_PROFILES=ntfy
   LISTA_NTFY_PUBLIC_URL=https://ntfy.example.com
   ```

   ```bash
   docker compose up -d ntfy
   ```

2. 送信用のユーザーを作り、`lista-*` のトピックの書き込みをそのユーザーだけに、読みを誰にでも許します。パスワードは聞かれるので、ランダムな値を入れます（トークンで送るので、後で使いません）

   ```bash
   docker compose exec ntfy ntfy user add lista-publisher
   docker compose exec ntfy ntfy access lista-publisher 'lista-*' write-only
   docker compose exec ntfy ntfy access everyone 'lista-*' read-only
   docker compose exec ntfy ntfy token add lista-publisher
   ```

3. 出たトークン（`tk_` で始まる）を `.env` に入れ、Lista を作り直します

   ```bash
   LISTA_NTFY_BASE_URL=http://ntfy
   LISTA_NTFY_TOKEN=tk_...
   ```

   ```bash
   docker compose up -d webapp
   ```

4. リバースプロキシで `https://ntfy.example.com` を `http://127.0.0.1:2586` へ転送します。**ntfy には WebSocket の転送が要ります**（アプリが通知を待つ接続に使います）。Caddy なら `reverse_proxy 127.0.0.1:2586` で足ります

### 確かめ方

- `docker compose exec ntfy ntfy access` に、`lista-publisher` の `write-only access to topic lista-*` と、`*` の `read-only access to topic lista-*` が出ます
- `curl -s -o /dev/null -w '%{http_code}\n' -d x http://127.0.0.1:2586/lista-test` が `403` を返します（トークンが無いと送れない）
- 「自分の設定」に ntfy の枠が出ます。「ntfy で受け取る」を押して購読し、「テスト送信」で届きます

### 知っておくこと

- **読みを誰にでも許すので、トピック名が合言葉になります。** トピック名は Lista が推測できない形（`lista-` に続く 26 文字。130 ビットの乱数）で作り、利用者には選ばせません。購読する URL を知った人は、ntfy に届く場所から通知を読めます。漏れたら、本人が「作り直す」を押します
- トークンに期限はありません。漏れたら `docker compose exec ntfy ntfy token remove lista-publisher <トークン>` で消し、作り直してください
- **iPhone の ntfy アプリには、自前のサーバーだけではすぐに届きません。** Apple の通知の中継を使うには ntfy の `NTFY_UPSTREAM_BASE_URL` の設定が要り、送り先に ntfy.sh が加わります。入れるかは、自分の組織の決まりで判断してください。同梱の compose には入れていません
- ntfy の中のデータ（ユーザー・トークン・24 時間で消える通知の控え）は、手順 2 で作り直せます。利用者ごとのトピックは Lista の DB にあります
