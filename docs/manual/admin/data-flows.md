# データの送り先

Lista が外へ送るものの一覧です。**配布元（Lista を配っている会社）へは何も送りません。** 利用状況の送信や、更新の確認もしません。送り先はすべて、導入した組織が設定したものか、利用者のブラウザが読みに行くものです。

## サーバー（Lista のコンテナ）から送るもの

| 送り先 | いつ | 送るもの | 止め方 |
|---|---|---|---|
| ログインのプロバイダ（`LISTA_OIDC_ISSUER_URI`） | 起動のとき（設定の取得）と、ログインのたび | ログインの手続きに要る値（クライアント ID・シークレット・認可コード） | 止められません（ログインに要る） |
| `api.anthropic.com`（Anthropic PBC・米国） | 利用者が Outlook のメールから追加画面を開いたときだけ | メールの件名・差出人の表示名（無ければメールアドレス）・受信日時・本文の先頭 30,000 字 | `ANTHROPIC_API_KEY` を空にする |
| ntfy のサーバー（`LISTA_NTFY_BASE_URL`） | 朝のまとめ・担当の知らせ・テスト送信のとき | 通知の本文（タスク名・相手・期限・サブタスク名・担当にした人の氏名・Lista の URL） | `LISTA_NTFY_BASE_URL` を空にする |
| 各 PC の IP メッセンジャー（LAN の中・UDP 2425・暗号化なし） | 同上。在席の確認は 8〜18 時の毎時 | 通知の本文（同上）。在席の確認には Lista の名乗りだけ | ホストのネットワークで動かさない（同梱の compose の既定） |
| PostgreSQL | 常に | Lista のすべてのデータ | — |

- AI へ送るものと送らないものの詳しい区別は [AI の下書き](ai.md) にあります
- ntfy を自前で立てる場合、通知は自分のサーバーの外へ出ません。ntfy の設定で iPhone 向けの中継（`NTFY_UPSTREAM_BASE_URL`）を入れると、ntfy.sh へメッセージの ID のハッシュが渡ります。本文は渡りません。同梱の compose には入れていません
- イメージの取得（`docker compose pull`）では、`ghcr.io`（GitHub）からダウンロードします

## 利用者のブラウザが読みに行くもの

画面の見た目と操作の部品を、次の配信元から読みます。読むときに、利用者の IP アドレスなどが配信元に伝わります。業務のデータは送りません。

| 配信元 | 読むもの | どこで |
|---|---|---|
| `cdn.jsdelivr.net` | Bootstrap（画面の部品）・Bootstrap Icons | すべての画面 |
| `cdn.jsdelivr.net` | flatpickr（月を選ぶ部品） | 月の記録 |
| `cdnjs.cloudflare.com` | SortableJS（ドラッグで並べ替える部品） | タスクとテンプレートの入力画面・テンプレートの一覧 |
| `appsforoffice.microsoft.com` | Office.js | Outlook のアドインの中だけ |

- どれも版を固定し、中身のハッシュ（integrity）を照らして読みます
- 利用者の端末からこれらの配信元へ出られないと、画面の見た目と操作が崩れます

## Lista の中に残るもの

- 業務のデータはすべて PostgreSQL に入り、Lista が期限を決めて消すことはありません。利用者が消したタスクは、その添付ごと DB から消えます。ログインのセッションは、期限が切れると消えます
- 通知の履歴（いつ、誰へ、どの経路で送ったか）を DB に残します。ntfy のトピック名は履歴に残しません
- ログには、利用者とタスクを ID で書いています。メールアドレス・通知の本文・メールの本文・AI の下書きは出さないようにしています。ただし、思わぬ失敗のときに出る例外の詳細には、値が含まれることがあります
